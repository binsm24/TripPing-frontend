# TripPing
사용자 요구 기반 당일치기 최적화 확장형 관광 코스 추천 서비스

## 📌 Git Convention

### 🔵 Commit Convention

- `Feat` : 새로운 기능 추가
- `Fix` : 버그, 오류 해결
- `Modify` : 코드 수정 (기능의 변화가 있을 때)
- `Docs` : README나 WIKI 등의 문서 수정
- `Remove` : 폴더 또는 파일 삭제, 쓸모없는 코드 삭제
- `Rename` : 파일 이름 변경 또는 파일 이동시
- `Refactor` : 기능 추가나 버그 수정이 없는 코드 변경 ( 코드 구조 변경 등의 리팩토링 )
- `Style` : 코드 formatting, 세미콜론 누락, 코드 자체의 변경이 없는 경우
- `Design` : CSS 등 사용자 UI 디자인 변경
- `Chore` : src 또는 test 파일을 수정하지 않는 기타 변경 사항 ( 빌드/패키지 매니저 설정 변경 등 )
- `Merge` : merge 하는 경우
- `Hotfix` : 급하게 치명적인 버그를 고쳐야 하는 경우

### 커밋 예시

- git commit -m "#이슈번호 커밋 태그: 커밋 내용"
    - ex) `git commit -m "#198 Feat: Header 기능 구현"`

<br>

### 🔵 Branch Convention

- `main` : 최종 배포
- `develop` : 주요 개발, main merge 이전에 거치는 branch
- `feat` : 각자 개발, 기능 추가
- `fix` : 에러 수정, 버그 수정
- `docs` : README, 문서
- `refactor` : 코드 리펙토링 (기능 변경 없이 코드만 수정할 때)
- `modify` : 코드 수정 (기능의 변화가 있을 때)

### 브랜치 명 예시

- feat/#이슈번호-기능 이름
    - ex) `feat/#21-header`

<br>

### 🔵 Branch Strategy

- Git-flow 전략을 기반으로 `main`, `dev` 브랜치와 `feat` 보조 브랜치를 운용했습니다.
- `main`, `dev`, `feat` 브랜치로 나누어 개발을 하였습니다.
    - `main` 브랜치는 배포 단계에서만 사용하는 브랜치입니다.
    - `dev` 브랜치는 개발 단계에서 git-flow의 master 역할을 하는 브랜치입니다.
    - `feat` 브랜치는 기능 단위로 독립적인 개발 환경을 위하여 사용하고 merge 후 각 브랜치를 삭제해주었습니다.

<br>

### 🔵 Issue Convention

- [Feat] : 기능 추가
- [Fix] : 에러 및 버그 수정
- [Docs] : README 등 문서
- [Refactor] : 코드 리펙토링 (기능 변경 없이 코드만 수정할 때)
- [Modify] : 코드 수정 (기능의 변화가 있을 때)
- [Chore] : 그 외 작업 내용

### 이슈 명 예시

- [이슈 항목] 개발 내용
    - `ex) [Feat] Header 구현`

# TripPing: 사용자 요구 기반 당일치기 최적화 확장형 관광 코스 추천 서비스

> 2026 관광데이터 활용 공모전

## 서비스 소개

기존 관광 추천 서비스는 동행자 구성, 여행 목적 등 사용자의 다양한 여행 상황을 충분히 반영하지 못하는 한계가 있습니다. 예를 들어 대학생과 초등학생 동생이 함께 나들이를 계획할 때 '아이 동반' 조건으로 검색하면 키즈카페나 박물관 같은 획일적인 장소만 추천되는 식입니다.

본 서비스는 자연어 입력과 선택형 조건을 결합해 사용자 요구를 정밀하게 분석하고, 핵심 관광지를 중심으로 주변 코스를 단계적으로 확장하는 **거점 기반 확장형 추천 구조**를 통해 당일치기 여행에 최적화된 맞춤형 코스를 제공합니다.

## 주요 기능

| 기능 | 설명 |
|---|---|
| 조건/자연어 기반 관광지 추천 | 여행 타입(자연/도시/복합), 연령, 동행자(연인/아이/가족), 지역 등 선택 조건 + 자유 텍스트 입력 |
| 주요 관광지 선택 및 확장 추천 | 주요 관광지 3곳 추천 → 사용자가 선택한 곳을 중심으로 주변 명소·식당·카페 확장 추천 |
| 코스 카드 생성 및 공유 | 확정 경로를 카드 형태로 시각화, 저장 및 SNS 공유 지원 |
| 코스 카드 보관함 | 생성된 코스 카드를 한눈에 모아보는 보관함 제공 |

**서비스 흐름**: 여행 조건 입력 → 추천 관광지 선택 → 코스 카드 생성


## 차별성

- 필터 기반 나열식 추천이 아닌, 자연어+조건 결합으로 사용자 의도를 정교하게 반영
- 추천 결과를 단순 수용하는 대신 사용자가 직접 관광지를 선택하고 코스를 확장해 나가는 능동적 참여 구조
- 효율적 동선의 당일치기 코스 + 직관적인 카드형 시각화 및 공유


## 발전 방향

- 대화형 인터페이스 도입으로 실시간 요구사항 반영
- 코스 카드 평점·피드백 기능 추가
- 보관함 카드형/지도형 UI 선택 제공
- 코스 공유·평가 커뮤니티 기능 확장
- 축적 데이터 기반 개인화 추천 알고리즘 고도화

## 기대효과

- 제한된 시간 내 효율적인 당일치기 여행 계획 지원, 사용자 만족도 향상
- 거점 확장형 구조를 통한 맥락 기반 여행 코스 제공
- 카드형 공유 콘텐츠 확산으로 숨겨진 관광지 발굴 및 지역 관광 활성화
